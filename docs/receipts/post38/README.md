## The one thing the new check reports rather than asserts

The compact row's Watch link sits flush with the page root's own padding at
320px and 390px, so the left segment of its focus ring falls outside
`.hackertube`'s `overflow-x: hidden` and is cut away entirely. The check reports
it instead of reading it as a 1:1 contrast reading:

```
REPORT at 320px the compact row's Watch link left: the ring is clipped by hackertube (0/163 painted) — not a contrast reading
REPORT at 390px the compact row's Watch link left: the ring is clipped by hackertube (0/163 painted) — not a contrast reading
```

That is a clipping defect in the compact row at those two widths, reported here
and in the pull request; **no CSS was changed**. Every side the ring does paint
on reaches 17.72:1 (compact) and 16.12:1 (full card, against the media column) /
17.72:1 (against the card). The tolerance is bounded: a side that is *partly*
clipped fails, and the ring overall must be ≥50% painted.

## The one flaky failure seen

One of the four full Node suite runs on this branch failed
`PREF16 interest remove button works by keyboard and stays removed after reload`
in `tests/test_browser_requests.js` (`1 !== 2` on its feed-reread count — a race
in that test's own assertion, not a change of this branch). That test file is
untouched by this branch, the test passes 3/3 in isolation, and the three later
full runs are clean. The rate is therefore 1 in 4 observed, and the file/line is
named above rather than left as "a flake".
