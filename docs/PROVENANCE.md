# Project provenance and entrant declaration

On November 8, 2026 Robert confirmed that he is entering solo and is authorized to license HackerTube under MIT. He stated that, to his knowledge, no code was copied from Andrej Karpathy; the inspiration was the idea. The existing About/README credit identifies this as an independent Hermes adaptation inspired by Karpathy's original HackerTube.

The repository records its own Python/dashboard implementation and source adapters; no Karpathy code import, submodule or bundled upstream HackerTube tree was identified in this review. This is a scoped repository/provenance check and Robert's declaration, not a claim that every transitive development dependency or data provider grants rights to all external content. The project LICENSE is MIT. Hermes remains the host; Node/Python development dependencies retain their own licenses. Source metadata/media links remain governed by their respective source terms. No media collection is bundled.

The official announcement provides no additional detailed entrant/team/pre-existing-work/IP clauses beyond its broad plugin invitation. No unobserved rule is inferred, and no organizer approval is represented. Robert's solo/MIT/idea-only declaration resolves the project's previously unanswered entrant-information gate; any later specific organizer rule still needs to be checked against the declaration.

The attribution PNG embedded as a data URI in `hackertube/dashboard/dist/index.js` is an unmodified Google/YouTube trademark asset from the official [brand download](https://brand.youtube/youtube-icon/) (`YouTube_Icon/Digital/01 Red/yt_icon_red_digital.png`). It is used only as linked source attribution, with the published minimum height and clear space. The MIT grant covers this project’s code, not Google/YouTube trademarks; their [branding guidelines](https://developers.google.com/youtube/terms/branding-guidelines) govern that asset. No provider media, artwork or player is bundled.

Official icon SHA-256: `1027b1b0517727adb9697155a270744381c3ce9b047b1c8bd8a9389dc7d07a83`. The browser regression decodes the data URI and verifies this exact original digest, successful image decoding, and the published minimum measured on the visible red mark rather than on the file box: the asset's built-in clear space is 578/1075 of its height, so both the compact row and the full feed card draw the image at 186px for a 100px visible mark. No separate backend asset route or duplicate binary is needed.

YouTube video thumbnails are **not** bundled, downloaded, or cached. When an explicit Search uses the configured Data API, the adapter keeps the official `https` thumbnail URL the `videos.list` payload returned, stores it only after one `free` GET of that public host confirms a `200` `image/*` answer, and the page hotlinks it. Developer Policies III.E.1 forbid downloading or storing copies of YouTube audiovisual content without prior written approval, so no image bytes are kept and `art_cache` stays `false`. The image is displayed at its own aspect ratio with no crop and no overlay, and the official linked Icon is shown beside it. This mirrors the existing Open Library cover hotlink policy.
